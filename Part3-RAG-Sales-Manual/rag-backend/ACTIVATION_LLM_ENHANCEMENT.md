# Activation Feature LLM Enhancement

## Overview
Enhanced the Activation Feature Service to use **Granite 4 LLM** (not TinyLlama) to generate clear, concise descriptions from raw Sales Manual chunks. This addresses the issue of messy, repetitive, or unclear activation feature descriptions.

**Important**: This feature uses the Granite service for its enhanced capabilities, not the basic TinyLlama used in earlier demo stages.

## Problem
The Sales Manual chunks often contain:
- Repetitive information across multiple features
- Unclear formatting with conversion tables
- Feature codes mixed with descriptions
- Too much or too little information per feature

Example of messy output:
```
- EDAR: (#EDAR) -512 GB Base Memory activation (Pools 2.0) from Static Feature EDAR not orderable in China (#EDAS) -500 GB Base Memory activation (Pools 2.0) from Static Feature EDAS not orderable in China...
```

## Solution
The service now:
1. **Extracts raw chunk text** containing activation features
2. **Sends FULL chunk to Granite LLM** with a focused prompt asking for a clear description
3. **Falls back to manual extraction** if LLM fails
4. **Cleans up output** by removing duplicate feature codes and organizing by category
5. **Adds AI-generated disclaimer** to inform users descriptions may contain inaccuracies

**Important Implementation Details:**
- **Uses Granite service** (not TinyLlama) for enhanced capabilities
- **Passes FULL chunk text** to LLM for better context understanding
- **Temperature: 0.2** - Lower temperature for more focused, factual output
- **Max tokens: 120** - Ensures concise one-line descriptions
- **Timeout: 15 seconds** - Allows time for Granite processing

The Granite LLM is prompted to provide:
- Type of activation (processor/memory)
- Capacity or amount
- Important restrictions (e.g., "not orderable in China", "Linux only")
- One sentence maximum (100 words)

### 3. Better Output Formatting
The `generate_activation_answer` method now:
- Organizes features by category (Processor/Memory/Other)
- Removes duplicate feature codes from descriptions
- Uses cleaner HTML formatting with `<em>` tags for categories
- Properly formats discontinued features

## Configuration

### Environment Variables
- `GRANITE_HOST`: Hostname of the Granite LLM service (default: `granite-llama-service`)
- `GRANITE_PORT`: Port of the Granite LLM service (default: `8080`)

### Disabling LLM Descriptions
If needed, you can disable LLM-based descriptions:
```python
service = ActivationFeatureService(use_llm_descriptions=False)
```

## Benefits
1. **Clearer descriptions**: Granite LLM understands context and generates human-readable text
2. **Reduced repetition**: Each feature gets a unique, focused description
3. **Better organization**: Features grouped by type (processor/memory)
4. **Fallback safety**: Manual extraction still works if Granite is unavailable
5. **Consistent format**: All descriptions follow the same structure
6. **Full context**: Entire chunk is passed to Granite for better understanding
7. **Transparency**: AI-generated disclaimer informs users about potential inaccuracies

## Testing

## Performance Considerations
- **Granite LLM calls** add ~2-3 seconds per feature (with 15s timeout)
- **Full chunk processing**: Granite receives complete context for better accuracy
- Descriptions are generated once during feature extraction
- Results are cached in the ActivationFeature objects
- Fallback to manual extraction ensures reliability even if Granite is slow/unavailable
